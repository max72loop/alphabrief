## Le projet
AlphaBrief est un gestionnaire de patrimoine personnel mono-utilisateur.
Score 0-100 par ticker (fondamentaux 50%, technicals 25%, momentum 25%),
suivi des positions, backtests et détection de phase de cycle Bitcoin.

Ce n'est plus un SaaS. Le screener multi-utilisateurs (Next.js sur Vercel,
Supabase, freemium, Lemon Squeezy) a été abandonné au pivot du 2026-07-31
et décommissionné le 2026-09-04. Il n'y a ni frontend, ni compte, ni
abonnement, ni facturation, ni Supabase. Voir AUDIT_PIVOT_2026-07-31.md.

Stack :
- Backend Python : core/generator.py → core/scoring/ → core/storage/writer.py
- DB : Postgres local (ticker_scores, watchlists, watchlist_tickers, positions,
  supports, societes, flux, snapshots, score_history, ticker_events)
- Data : yfinance + FMP (core/providers/)
- LLM : DeepSeek (deepseek-chat) pour one_liner, moat_tags, catalysts

## Ce que tu peux faire sans demander
- Lire n'importe quel fichier du projet
- Modifier du code Python
- Lancer : python -m core.cli analyze TICKER, python -m core.cli status
- Commiter et pusher du code (git add → git commit → git push)
- pm2 restart alphabrief après une modif du scheduler

## Ce que tu dois demander avant de faire
- Modifier les variables d'environnement (/root/.env)
- Faire un pm2 delete ou modifier /root/agents/alphabrief/ecosystem.config.js
- Supprimer des tables ou des colonnes Postgres
- Pousser sur une branche protégée ou force push

## Règles absolues
- Ne jamais commiter .env
- Ne jamais mentionner "conseil en investissement"
- Toujours cacher les appels FMP avant de les faire (rate limits)
- Préférer FMP à yfinance pour les nouvelles features data
- Le score est calculé dans core/scoring/potential.py — ne pas casser les poids
- Ne jamais `git clean` dans /root/alphabrief ni /root/agents/alphabrief :
  des modules atteints par le daemon y ont déjà traîné non versionnés
- Ne jamais lancer `pm2 startOrReload /root/infra/ecosystem.config.js` :
  son max_memory_restart plus bas tue le scoring en cours de boucle

## Schéma Postgres (colonnes clés)
ticker_scores : ticker, company_name, sector, exchange, currency, market_cap,
one_liner, moat_tags, score_total, score_fundamentals, score_technicals,
score_momentum, score_label, importance_items (jsonb), financials (jsonb),
market_data (jsonb), score_date, computed_at

watchlists : id
watchlist_tickers : watchlist_id, ticker

Les tables paper_* sont vestigiales : le paper trading a été retiré le
2026-08-22 et plus rien ne les écrit.

Commence par faire `pm2 status` et `python -m core.cli status` pour évaluer l'état du système.

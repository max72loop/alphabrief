## Le projet
AlphaBrief est un screener quantitatif d'actions. Score 0-100 par ticker (fondamentaux 50%, technicals 25%, momentum 25%). Freemium : 5 analyses/jour gratuites.

Stack :
- Backend Python : core/generator.py → core/scoring/ → core/supabase_sink.py
- Frontend Next.js 14 (App Router, Tailwind v4, Supabase SSR)
- DB : Supabase (ticker_scores, profiles, watchlists, watchlist_tickers)
- Data : yfinance (migration FMP prévue)
- Paiements : Lemon Squeezy (webhook OK, checkout URL à configurer)
- LLM : DeepSeek pour one_liner, moat_tags, catalysts

## Ce que tu peux faire sans demander
- Lire n'importe quel fichier du projet
- Modifier du code Python ou TypeScript/TSX
- Lancer : python -m core.cli analyze TICKER, python -m core.cli status
- Lancer : npm run build (dans alphabrief-frontend) pour vérifier la compilation
- Lancer : node_modules/.bin/tsc --noEmit pour vérifier les types TypeScript
- Commiter et pusher du code (git add → git commit → git push)
- pm2 restart alphabrief après une modif du scheduler

## Ce que tu dois demander avant de faire
- Modifier les variables d'environnement (.env / .env.local)
- Faire un pm2 delete ou changer le cron_restart dans ecosystem.config.cjs
- Supprimer des fichiers ou colonnes Supabase
- Toucher aux politiques RLS Supabase
- Pousser sur une branche protégée ou force push

## Règles absolues
- Ne jamais commiter .env ou .env.local
- Ne jamais mentionner "conseil en investissement"
- Toujours cacher les appels FMP avant de les faire (rate limits)
- Préférer FMP à yfinance pour les nouvelles features data
